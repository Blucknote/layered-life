# Техническое задание: трёхслойная «Жизнь»

## 1. Задача для агента

Реализовать работающий интерактивный браузерный прототип клеточного автомата: три двумерных поля, расположенных этажами в 3D. Живая клетка отображается кубиком, мёртвая — пустым местом. Клетки взаимодействуют внутри своего слоя и с соседними слоями. Пользователь расставляет кубики, запускает симуляцию, меняет правила и наблюдает результат.

Это исследовательская игрушка для поиска интересного поведения. На этом этапе не нужны сюжет, уровни, победа, ресурсы, персонаж, физический движок или генерация графических ассетов. Не подменять заданные правила более зрелищными без явного выбора пользователя. Затухание и переполнение — допустимые результаты эксперимента.

Довести реализацию до запускаемого приложения, а не остановиться на плане. Результат: исходники, инструкция запуска, проверенная сборка и краткий отчёт о проверках. Публикация не входит в задачу.

## 2. Выбор технологий

Предлагаемый стек: TypeScript, Vite, Three.js, HTML/CSS для интерфейса, Vitest для тестирования автомата. React не требуется. Версии зависимостей подобрать совместимые на момент реализации и закрепить lockfile. Скрипты: `dev`, `build`, `test`.

Всё выполняется локально в браузере. Серверный бэкенд, Python-сервис, БД, аккаунты и сетевые API не нужны. Dev-сервер служит только для запуска приложения. Зависимости включать в сборку, не загружать библиотеки с CDN во время работы приложения.

Three.js отвечает за камеру и отображение 3D через WebGL в canvas. Canvas 2D и собственный 3D-рендерер не использовать: они добавят работу с проекцией, перекрытиями и выбором клеток без пользы для этого эксперимента. Godot допустим для дальнейшего самостоятельного игрового проекта, но для текущей небольшой браузерной лаборатории выбран веб-стек.

Официальные ссылки для реализации:

- https://threejs.org/docs/
- https://threejs.org/docs/pages/InstancedMesh.html — инстансинг кубиков сокращает число вызовов отрисовки.

## 3. Модель мира и начальные параметры

| Параметр | Значение |
| --- | --- |
| Размер поля | 32 × 32 клетки |
| Число слоёв | Ровно 3 в интерфейсе MVP |
| Координаты | x, y — внутри поля; z = 0, 1, 2 — номер этажа |
| Состояние | 0 — мёртвая клетка; 1 — живая |
| Границы | За всеми границами пустота; без зацикливания |
| Соседство | 8 клеток своего слоя + непосредственно верхняя и нижняя |
| Рождение B | {3} |
| Выживание S | {2, 3} |
| Межслойная связь | Включена |
| Скорость | 5 поколений/с, настройка 1–30 |
| Старт | Непустая воспроизводимая конфигурация, симуляция на паузе |

Число слоёв в ядре хранить как параметр, но не добавлять в MVP интерфейс произвольных измерений. При необходимости начать с 32 × 32; изменение размера поля пользователем не обязательно.

## 4. Точные правила

Для клетки (x,y,z) внутрислойные соседи — (x+dx,y+dy,z), где dx,dy принадлежат {-1,0,1}, кроме пары (0,0). При включённой межслойной связи дополнительно учитывать (x,y,z−1) и (x,y,z+1). Диагональные соседи других слоёв не учитываются. Собственную клетку не учитывать.

Все соседи равноправны и имеют вес 1. Максимум — 10 у среднего слоя, 9 у крайних; на границах поля доступных соседей меньше. Отсутствующие координаты дают 0. Слои 0 и 2 напрямую не связаны.

Для числа живых соседей n:

```text
если current[cell] == 0: next[cell] = n принадлежит B
если current[cell] == 1: next[cell] = n принадлежит S
```

Обновление строго синхронное: всё следующее поколение вычисляется по неизменному предыдущему. Использовать два буфера; пересчёт «на месте» запрещён. Рождение и смерть дискретные, без состояний вспышки или восстановления.

При отключении связи остаются только восемь внутрислойных соседей: три независимые «Жизни» с общими B/S. Переключение связи само по себе не изменяет клетки.

Дать редактирование B и S отдельными наборами переключателей 0–10 и кнопку возврата к B={3}, S={2,3}. Это экспериментальное расширение «Жизни» с анизотропным соседством, а не обещание поведения классической 2D-версии и не соседство из всех 26 объёмных позиций.

## 5. Отображение

Главный экран — крупная 3D-сцена и компактная панель управления на русском. Все три слоя включены при запуске. Разные спокойные цвета кубиков обозначают этажи; легенда подписана. Фон контрастный, кубики непрозрачные, лёгкое освещение помогает читать грани. Не требуются тени, bloom и постобработка.

Каждый этаж обозначен тонкой сеткой. Стартовая камера — наклонная, смотрит на центр стопки. Вращение, приближение, перемещение камеры и кнопка сброса ракурса обязательны. Предпочтительно использовать OrbitControls.

Сторона кубика примерно 0.8 относительно шага сетки 1. Расстояние этажей по умолчанию 2.5, ползунок 1–6. Это только визуальное раздвижение: расстояние никак не меняет соседство и правила. Координаты модели отделить от координат сцены; например, высота сцены Y соответствует номеру слоя z.

У каждого этажа есть переключатель видимости. Скрытие влияет только на отрисовку; скрытый слой продолжает участвовать в расчёте. Подписать это в интерфейсе. Для удобного редактирования среднего слоя пользователь может скрыть остальные.

Не обещать одновременную видимость каждого кубика: объекты могут перекрывать друг друга. Раздвижение, вращение и скрытие слоёв должны позволять их рассмотреть.

## 6. Взаимодействие и управление

Обязательные элементы:

- Старт/пауза; одиночный шаг, который оставляет симуляцию на паузе.
- Скорость 1–30 поколений/с; число поколения и живых клеток всего и на каждом этаже.
- Выбор активного слоя 1/2/3 и инструмента «Камера / Добавить / Удалить».
- Случайное заполнение с плотностью 0–100%, по умолчанию 15%, и целочисленным seed.
- Очистка всех слоёв.
- B/S, переключатель межслойной связи и возврат базовых правил.
- «Запомнить старт» и «Вернуть старт» для сравнения экспериментов.
- Экспорт и импорт эксперимента JSON.

Добавление и удаление работают по клеткам активного этажа, включая пустые. Использовать пересечение луча камеры с плоскостью активного слоя, а не только выбор существующего кубика. Под курсором показывать контур целевой клетки. За пределами поля действие игнорируется. При выборе скрытого слоя сделать его видимым.

В режиме камеры перетаскивание вращает вид. В режимах добавления/удаления основная кнопка редактирует, вращение этим жестом отключено; зум доступен. На MVP достаточно одиночных кликов без рисования кистью. Начало редактирования ставит симуляцию на паузу. Нажатия на UI не должны менять клетки.

Изменение B/S или связи ставит симуляцию на паузу, сохраняет текущее поле и номер поколения; следующие шаги используют новые правила. Изменение скорости и параметров отображения не сбрасывает мир.

Очистка и случайное заполнение ставят паузу, обнуляют поколение и делают полученное поле новым сохранённым стартом. Начальная демонстрационная конфигурация также является сохранённым стартом. «Запомнить старт» копирует текущее поле и обнуляет поколение. «Вернуть старт» восстанавливает копию клеток и обнуляет поколение, но сохраняет текущие B/S и связь: так один старт сравнивается при разных правилах.

Случайное заполнение использует явно определённый детерминированный PRNG с документированным алгоритмом. Одинаковые seed, размеры и плотность дают одинаковые клетки. Не использовать Math.random для воспроизводимого заполнения.

Горячие клавиши: Space — старт/пауза, N — шаг, 1/2/3 — активный слой. Не перехватывать их при вводе в поля формы.

## 7. Сохранение экспериментов

JSON содержит: formatVersion, размеры, текущее поле, сохранённое стартовое поле, поколение, B/S, состояние связи, скорость, seed и плотность. Формат массива и порядок координат документировать. Камеру сохранять необязательно.

Импорт восстанавливает эксперимент на паузе. Проверять версию формата, размеры (32 × 32 × 3 для MVP), длины массивов, бинарные значения клеток, диапазоны B/S и числовых параметров. Некорректный файл показывает понятную ошибку и не портит текущий мир. Ограничить размер импортируемого файла, например 1 МБ. Экспорт → импорт должен сохранять состояние и последующее поведение.

## 8. Архитектура и производительность

Отделить чистое ядро симуляции от DOM и Three.js. Пример разделения: simulation (состояние, соседство, step), presets/random, serialization, renderer, controls/UI. Состояние хранить в Uint8Array; задокументировать формулу индекса, например x + width * (y + height * z).

Расчёты MVP выполняются на CPU. Web Workers, GPU compute, WebGPU и шейдерная симуляция не нужны без выявленной проблемы. Отрисовывать кубики через InstancedMesh, например один на слой; переиспользовать геометрию и материалы. Обновлять матрицы после изменения состояния, не создавать тысячи отдельных Mesh каждый кадр.

Скорость симуляции отделить от FPS через накопитель времени. Ограничить число догоняющих шагов за кадр, чтобы приложение не зависало. При уходе вкладки в фон поставить паузу, при возвращении не проигрывать накопившееся время. Камера должна работать и на паузе. Обрабатывать изменение размера окна, ограничить pixel ratio разумным значением, например 2.

Целевая среда — настольный браузер, в том числе Safari на Apple Silicon. Ориентир: отзывчивое вращение поля 32 × 32 × 3 при 10 шагах/с. Замерить на доступной машине и указать среду; не заявлять проверку Safari или целевого оборудования, если их нет. При отсутствии WebGL показывать понятное сообщение вместо пустого экрана.

## 9. Проверки и критерии приёмки

Проверки ядра автоматизировать:

1. При отключённой связи блок 2 × 2 внутри слоя стабилен, трёхклеточный блинкер возвращается через два шага; остальные слои остаются пустыми при B3/S23.
2. Межслойное рождение: поле пустое, кроме (9,10,1), (11,10,1), (10,10,0). После шага клетка (10,10,1) рождается при включённой связи и остаётся мёртвой при отключённой.
3. Собственная клетка не считается соседом; межслойные диагонали не считаются; границы не зациклены; слои 0 и 2 не соединены напрямую.
4. Следующий шаг не мутирует входное поколение; результат соответствует синхронному обновлению.
5. Изменённые B/S применяются, включая n=0 и n=10; seed воспроизводим; JSON проходит round-trip, ошибочный JSON отклоняется.

Проверки интерфейса вручную или доступной браузерной автоматизацией:

- Три слоя различимы, камера вращается, раздвижение этажей не меняет результат шага.
- Можно добавить и удалить кубик на среднем этаже; перетаскивание камеры не создаёт клетки.
- Шаг увеличивает поколение ровно на один; пауза останавливает расчёт.
- Скрытый слой продолжает влиять на результат.
- Возврат старта сохраняет выбранные правила и восстанавливает исходные клетки.
- Экспорт, изменение мира и импорт возвращают сохранённое состояние на паузе.
- Сборка и тесты проходят; нет ошибок консоли в проверенном браузере.

В README описать запуск, правила, управление, формат JSON, алгоритм seed и ограничения. В отчёте отделить реально проверенное от непроверенного. Не считать красивую эмержентность критерием приёмки: прототип нужен именно для её поиска.

## 10. За пределами MVP

Не реализовывать сейчас 4D, изменение прошлого, произвольный граф связей, разные правила для каждого слоя, соседство 26, мультиплеер, редактор кода правил и игровую прогрессию. Возможность развития обеспечить разделением ядра и визуализации, без универсального движка «на будущее».
